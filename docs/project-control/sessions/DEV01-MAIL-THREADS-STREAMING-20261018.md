## Delivered directly on main

1. **Actual Mail Threads** — `apps/web/src/app/mail/threads/page.tsx` no longer shows fake "No live mailbox connected" when synced conversations exist. It derives active organization from the established authenticated request headers, loads first page of real PostgreSQL conversations and mailbox selector options, distinguishes missing auth/database/provider query errors from empty results.
2. **Tenant-safe repository pagination** — `packages/db/src/email/repository.ts` adds `listMailThreadsForOrganization` and `MailThreadFilters`; `packages/db/src/index.ts` exports them. SQL joins each message to a thread and email account within the *same organization and account*, excludes deleted mailboxes, chooses latest message per thread using `ROW_NUMBER`, computes message/unread counts (excluding sent/draft from unread), searches all messages in the thread with SQL parameters, bounds pages (25 default, 50 max; offset <= 10000). No email HTML/full body returned in list summaries.
3. **Authorized API and accessible Threads UI** — `GET /api/mail/threads` checks `organization.read` *before* query, validates limits/UUID and sets private/no-store. Client supports per-mailbox filtering, unread filter, search, pagination with deduplication, direct thread links, no-match vs no-sync vs error, aborting stale fetches before filter changes, clear filters and mobile-friendly list.
4. **Chat + voice focus** — Chat mobile header wraps; when the embedded VoiceWorkspace closes, keyboard focus returns to the text composer, preserving the draft and existing chosen agent.
5. **True token streaming (non-tool model path)** — shared incremental browser SSE decoder `apps/web/src/lib/streaming/sse.ts`; Chat consumes SSE `delta` events as they arrive, updates assistant text live, shows status before first token, and rejects incomplete EOF. `/api/chat/stream` sends conversation/status early and actual model delta events as they arrive; conversational prompts go directly to Clara streaming, while potentially actionable email/WhatsApp tool prompts remain inside the existing authorized/bounded tool loop. No fake character-by-character animation of a completed response.
6. **Realtime voice progressive text** — `POST /api/voice/turn` remains backward-compatible with original JSON mode but supports `Accept: text/event-stream` after the SAME existing org/member/agent/user-session/active-session and turn-count authorization. For non-tool conversational prompts, `claraRuntime.createChatTurn` yields real model tokens over SSE. For email/account/tool-sensitive turns, it executes the existing `runEmailAgentTurn` with unchanged tool policy/approval; progress status arrives first, final tool answer is emitted only after completion (no claim of per-token tool stream). VoiceWorkspace now renders partial assistant text with a streaming state, preserves partial content on failure, and triggers current speech/TTS path after completed answer.
7. **Provider transport** — Clara Gemini generator upgraded from blocking `:generateContent` JSON to actual `:streamGenerateContent?alt=sse` incremental token events. OpenAI/Sarvam-compatible SSE reader now handles split UTF-8, EOF-final events, bounded frames and reader cleanup. Direct model generation is explicitly instructed that external resource mutations require host tools/approval.
8. **Tests** — `apps/web/tests/mail-threads-workspace.test.ts` and `apps/web/tests/streaming-conversations.test.ts` Vitest source-contract suites created, plus Node-runtime `apps/web/tests/sse-streaming.test.mjs` for actual parser behavior.
