## Confirmed root cause
- `apps/web/src/lib/ai/live-model-catalog.ts` only supported Sarvam chat and ElevenLabs TTS/STT; `GET /api/settings/ai-models?purpose=realtime` rejected both before any model-list call. The green badge meant the per-purpose API key was saved/enabled, not realtime model availability.
- Sarvam `GET /v2/models` is a **chat** completion catalogue, not a streaming STT model-list endpoint. The documented realtime STT WebSocket accepts `saaras:v3-realtime` and `saaras:v4`. Vendor docs: https://docs.sarvam.ai/api/api-guides-tutorials/speech-to-text/realtime-streaming
- The currently deployed application's ElevenLabs realtime relay is Scribe `scribe_v2_realtime` STT + host authorized Clara agent + streaming ElevenLabs TTS. This is **not** ElevenLabs Conversational AI's different `/v1/convai/agents` + signed WebSocket API. The historical static `elevenlabs-conversational` entry is not a valid STT model ID. Vendor docs: https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime and https://elevenlabs.io/docs/eleven-agents/api-reference/conversations/get-signed-url

Clara runtime validates selected Sarvam ID; relay bootstrap uses the persisted session model.
