## Decisions, failed approaches and lessons
- Rejected building a second scheduler, writing automatic WhatsApp send on an AI prompt, guessing five days of inactivity from an explicit five-day mail lookback, and using a browser query to pick arbitrary mailbox IDs. These would bypass consent/privacy or misreport runtime progress.
- Reuse the already-existing `/scheduled` schedule/automation systems, the existing per-user grant/manifest C1/C2, and R1a canonical occurrence clock. **A preview is a planning artifact, not authorization.**
- Need to separately distinguish last foreground visit, last completed review and last delivered digest; the app opening itself does not acknowledge mail, and absence detection is not employee surveillance.
- Later deliver an actual digest **only** after authorization is bound to exact mailbox scope, account/recipient/template, timezone/wall-clock vs interval, content limits, immutable proposal revision and human action, with runtime revocation and idempotent receipt checks. Keep WhatsApp per-message human approval until separate standing-digest grant is explicitly accepted.
