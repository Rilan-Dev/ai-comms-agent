# FIX-01 / Sentinel — WhatsApp error 131047 investigation
Date: 2026-10-17
Repository: Rilan-Dev/ai-comms-agent
Branch inspected: main
Status: provider rejection proven; delivery-state/UI follow-up needs runtime evidence

## Symptom
The user queued outbound text "Hii ACA Test" to a WhatsApp recipient. The API returned queued=true and a message ID, but the recipient received nothing. A Meta webhook status payload for the corresponding provider message ID reported status=failed with error code 131047 ("Re-engagement message"). The detail states that more than 24 hours have passed since the customer last replied.

## Root cause
Meta rejected the free-form text because the customer-service window had expired. Outside the 24-hour window, outbound re-engagement must use an eligible approved message template. Queue acceptance is not provider acceptance or delivery confirmation.

## Failed approaches / non-remedies
- Treating HTTP queue success as evidence of delivery.
- Repeating the same free-form text after Meta has explicitly rejected it.
- Reopening the 24-hour window by retrying; only a customer message reopens it.
- Removing connected-account, authorization, idempotency, webhook signature, or tenant-scope checks.
- Treating the earlier 42P10 SQL correction as a fix for provider error 131047.

## Remedy
No outbound send-policy code change is justified by this payload alone: Meta's rejection is expected behavior. Send an approved template for out-of-window re-engagement, or send free-form text only when the customer-service window is active.
Separately trace why the conversation UI says "sent" despite a supplied failed status. Check redacted webhook HTTP response/accepted count, exact provider_message_id match, persisted status/provider_error, serving commit, and UI refresh. Route deployment, live DB, webhook delivery, or runtime mismatch to OPS-01.

## Prevention lesson
Keep queued, provider-accepted/sent, delivered, read, and failed as distinct states. Surface Meta's failure code/details in the conversation UI. Add a regression test for status transition and error visibility only after confirming the current status mapper/UI behavior; do not encode a guessed fix.
